## 1. Что такое Reconciliation (Согласование)?

![hw-pic](/src/assets/Reconciliation-hw.png)

**Reconciliation** (согласование) — это алгоритм, с помощью которого React эффективно обновляет пользовательский интерфейс (DOM).

Когда у компонента меняются стейт (`state`) или пропсы (`props`), React создает новое виртуальное дерево элементов (**Virtual DOM**). Чтобы не перерисовывать всю страницу целиком (что работает очень медленно), React сравнивает новое дерево со старым (этот процесс называется *diffing*). На основе разницы React вычисляет минимальный набор точечных изменений и применяет их в реальном DOM. Это делает приложения на React быстрыми и производительными.

## 2. Зачем React нужен `key`?

Атрибут `key` — это уникальный идентификатор, который помогает React отслеживать элементы списка при их создании, изменении, добавлении или удалении.

* **Уникальность:** Помогает React понять, какой именно элемент перед ним.
* **Идентификация:** Без ключей React сравнивал бы элементы просто по порядку их следования. С ключом React точно знает: *«Этот элемент переместился с 3-й позиции на 1-ю, а не исчез и появился заново»*.
* **Сохранение состояния:** Ключи помогают сохранять внутреннее состояние компонентов (например, введённый текст в инпуте или состояние чекбокса) при перестановке элементов местами.

## 3. Почему индекс массива может быть плохим `key`?

Использование индекса массива (`index`) в качестве значения `key` — это **антипаттерн** во многих сценариях.

* **Проблема при изменении порядка:** Если элементы списка можно добавлять в начало, удалять или перемешивать, индексы сдвигаются. Элемент остается тот же, но его `key` меняется на новый индекс.
* **Баги интерфейса:** Из-за этого React может «попутать» элементы местами. Например, состояние или фокус ввода останется на старой позиции, хотя данные в строке изменились.
* **Ухудшение производительности:** React будет ошибочно пересоздавать DOM-узлы вместо того, чтобы просто переставить их местами.
* *Когда индекс допустим:* Только если список строго статичный: элементы никогда не удаляются, не добавляются в середину/начало и не меняют свой порядок.

* **При использовании индексов в качестве `key`:** Если честно, я ничего не заметила, потому что сложно ориентироваться в списке из 1000 элементов. Работали команды также быстро, скорее всего были какие-то баги связанные с изменением индексов и перерисовкой всех элементов вместо нескольких. Но видно этого не было.
* **При использовании уникальных ID:** Список стал вести себя стабильно и предсказуемо. При перемешивании и добавлении элементов React точно знал, какой компонент куда переехал, сохраняя всю его историю, фокус и состояние на месте, а перерисовки стали работать корректно.
